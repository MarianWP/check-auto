# Аудит Golf Check

Дата: 23 сентября 2026. Проверены клиент Vue, стили, хранение, синхронизация, чат, генерация, SQL-миграции, тесты и сборка. Исходники приложения не изменялись.

`npm.cmd test`: 10 файлов, 100 тестов успешно. `npm.cmd run build`: успешно, включая service worker. Основной JS: 597,15 КБ / 179,45 КБ gzip; CSS: 42,36 КБ / 8,90 КБ gzip; precache: 715,55 KiB. Сборка предупреждает о JS-файле больше 500 КБ.

Облачные сценарии анализировались по коду; запросы в рабочую базу и к платным AI-сервисам не отправлялись. Отдельные ошибки воспроизведены локально с подменой сетевого транспорта.

Приоритеты: **P1** — исправить прежде расширения функциональности; **P2** — следующая итерация качества; **P3** — улучшения по мере роста проекта. Подтверждённые ошибки отделены от предложений и рисков, требующих измерений.

**Что уже сделано хорошо**

- Чистая логика отчёта и нормализации выделена в `src/logic` и покрыта тестами.
- Есть локальное сохранение, резервные копии, обработка повреждённых данных и предупреждения о сбоях записи осмотров.

- Нижние панели находятся в потоке flex-контейнера. Это разумная основа мобильного интерфейса; переписывать `layout.css` целиком не требуется.
- SQL-миграции предусматривают RLS; ключи AI-провайдеров используются в серверных функциях.

**1. P1 — изменения во время отправки могут ошибочно считаться синхронизированными. Подтверждено воспроизведением.**

Место: `src/cloud/sync.js:32–44`.

`dirty()` возвращает ссылки на живые записи. После `await upsert(...)` код записывает в `meta.pushed` их текущий `updatedAt`, который мог измениться уже после формирования запроса. В воспроизведении отправлена версия 1000, во время запроса запись изменена до 2000, подтверждена версия 2000, `pending = 0`. Новое содержимое на сервер не отправлялось.

Аналогично после удаления очищается вся `meta.deleted`, включая потенциально добавленные во время запроса ID. Нет общей защиты от параллельных `push/fullSync`.

Исправление: фиксировать снимок payload и версий до запроса, подтверждать только отправленные версии и удаления; выполнять синхронизацию через единую очередь с повторным проходом при накоплении изменений.

Проверка: задержать ответ сервера, изменить запись и удалить ещё одну; после завершения очередь должна сохранять новые изменения и отправить их следующим запросом.

**2. P1 — после подтягивания облака открытый экран может редактировать объект, которого уже нет в хранилище. Подтверждено анализом и воспроизведением механики Vue.**

Места: `src/views/CheckView.vue:15`, `src/views/CarView.vue:19`, `src/views/ReportView.vue:15`; `src/cloud/sync.js:66–67`; `src/logic/storage.js:144`.

Экраны один раз получают `const i = insp(id)`. Слияние заменяет более старую запись новым объектом. Открытый экран продолжает держать прежнюю ссылку. В локальном воспроизведении ответ появился в объекте экрана, но отсутствовал в `db.inspections`.

Исправление: получать текущий осмотр через `computed(() => insp(id))` с обработкой отсутствующей записи либо обновлять существующие объекты на месте. Согласовать это с правилами разрешения конфликтов, чтобы облако не затирало локальное редактирование.

**3. P1 — локальные данные и кеш чата не разделены по аккаунтам. Подтверждено кодом.**

Места: `src/cloud/sync.js:12–16,90`, `src/cloud/auth.js:51–55`, `src/cloud/assistant.js:12–23`, `src/logic/storage.js:6–7`.

После выхода локальные осмотры, метаданные отправки и история чата остаются общими. Ключ общего чата — `none`, без ID пользователя. При входе другим аккаунтом кеш предыдущего может отобразиться до ответа сервера; при сбое останется как устаревшая история. В синхронизации возможны смешение локальных списков и конфликты записи из-за принадлежности ID другому пользователю. RLS защищает серверные строки, но не разделяет локальный кеш.

Исправление: пространство хранения по `user.id`, отдельный гостевой профиль и явный перенос гостевых осмотров при входе. При смене пользователя сбрасывать состояние чата и отменять запросы предыдущей сессии; проверять ID сессии после каждого `await`.

**4. P1 — удаление не распространяется надёжно между устройствами. Подтверждено кодом.**

Места: `src/cloud/sync.js:41–44,63–69,91–92`; `src/logic/storage.js:138–147`.

На сервере строка удаляется физически, а слияние только добавляет или заменяет записи. На втором устройстве старый осмотр остаётся, поскольку отсутствие строки в ответе не считается удалением. После редактирования он может снова загрузиться в облако. При возвращении сети и приложения в фокус вызывается только `push`, поэтому изменения другого устройства автоматически не подтягиваются этими событиями.

Исправление: хранить серверные отметки удаления с версиями, получать изменения вместе с удалениями, запускать последовательный pull/merge/push при восстановлении сети. Разрешать конфликты по серверной ревизии, а не только по часам устройства. Простое удаление всех локальных записей, отсутствующих на сервере, опасно для ещё не отправленных осмотров.

**5. P1 — очистка чата восстанавливает дневной лимит AI-запросов. Подтверждено кодом.**

Места: `supabase/functions/assistant/index.ts:108–114,144–148`; `src/cloud/assistant.js:87–94`; `supabase/migrations/20260923000000_assistant.sql:16–17`. Аналогичная схема подсчёта генераций — `supabase/functions/generate/index.ts:104–107`.

Использование вычисляется по числу сохранённых сообщений, которые пользователь может удалить. После очистки счётчик уменьшается. Параллельные запросы также способны одновременно пройти проверку, поскольку квота учитывается лишь после выполнения. Ошибка запроса подсчёта не проверяется: `null` трактуется как нулевое использование.

Исправление: отдельный журнал использования, не зависящий от удаления истории, и атомарное резервирование квоты до обращения к провайдеру. Определить правила учёта неудавшихся и отменённых запросов.

**6. P2 — в длинном чате загружаются первые 60 сообщений вместо последних. Подтверждено кодом.**

Место: `src/cloud/assistant.js:26–34`.

Запрос сортирует по возрастанию времени и затем применяет `limit(60)`. После 60 сообщений новые реплики пропадают из отображаемой истории при повторном открытии, хотя сервер их хранит. Облачный ответ также перезаписывает локальный кеш этим старым фрагментом.

Исправление: запрашивать последние сообщения по убыванию, разворачивать их для показа; более старую историю подгружать курсором с устойчивым порядком `(created_at, id)`.

**7. P2 — чат теряет введённый вопрос при ошибке и не позволяет остановить зависший ответ. Подтверждено кодом.**

Места: `src/views/AssistantView.vue:49–56,67–71`; `src/cloud/assistant.js:55–83`.

Поле очищается до запроса. При ошибке обе временные реплики удаляются, а текст в поле не возвращается. У запроса и чтения потока нет отмены или тайм-аута; `streaming` блокирует ввод. Во время ответа можно переключить осмотр: загрузчик меняет общий массив сообщений, а старый запрос продолжает работать и в конце может закешировать уже чужой разговор под предыдущим ключом.

Исправление: хранить статус каждой отправки, сохранять текст неудачного вопроса и кнопку повтора; добавить отмену, тайм-аут простоя потока, ID запроса и отдельное состояние по разговору. Перед записью результата сверять разговор и пользователя.

**8. P2 — 100% на чек-листе не означает, что автомобиль проверен. Подтверждено воспроизведением.**

Места: `src/logic/report.js:31–37,54–68`; `src/views/CheckView.vue:24,47`; `src/components/InspCard.vue:20`.

`skip` увеличивает прогресс этапов, но не полноту отчёта. В проверке на конфигурации с 103 пунктами все ответы «Не перевірено» дали 100% на экране осмотра и 0% в отчёте. Логика отчёта здесь разумна, неоднозначна подпись прогресса в интерфейсе.

Исправление: явно показывать «Проверено 42 из 103 · пропущено 8»; отличать просмотренные этапы от проверенных. При формировании неполного отчёта показывать число оставшихся критических пунктов с переходом к ним. Не блокировать возможность получить промежуточный отчёт.

**9. P2 — завершённый отчёт пересчитывается по изменяемому справочнику. Подтверждено архитектурой.**

Места: `src/store.js:16–18,133–138`; `src/cloud/content.js:11–14`; `src/logic/report.js:15–28`.

Осмотр хранит ответы и конфигурацию, но не версию чек-листа, цен и правил расчёта. Изменение или отключение пункта в админке способно изменить старый вердикт, бюджет или полноту без действий владельца осмотра.

Исправление: сохранять версию набора данных либо снимок применённых пунктов/стоимостей; для завершения сохранять снимок результата. Обновление старого осмотра на новый справочник делать отдельной явной операцией.

**10. P2 — стартовая загрузка включает все экраны. Измерено сборкой.**

Место: `src/router.js:8–21`.

Все 14 экранов, включая админку и AI, импортированы статически. Основной JS — 597,15 КБ, gzip — 179,45 КБ. Это измерение размера, а не доказательство конкретной задержки на телефоне.

Исправление: начать с динамических импортов админки, генерации и помощника; затем оценить разделение остальных маршрутов. Сохранить прогрев нужных ресурсов для офлайн-осмотра. Код основного Vue-runtime и общие данные не нужно искусственно дробить на множество микрофайлов. Такой подход соответствует [рекомендациям Vue по code splitting](https://vuejs.org/guide/best-practices/performance).

Проверка: сравнить стартовый JS и время до первого действия на холодном кеше и слабом устройстве; отдельно пройти офлайн-переходы после установки PWA. Precache может продолжать скачивать ленивые чанки в фоне, поэтому уменьшение стартового JS не равно уменьшению полного офлайн-пакета.

**11. P2 — каждый ввод затрагивает всё дерево осмотров. Потенциальное узкое место; браузерного профиля нет.**

Места: `src/store.js:78–90`; `src/cloud/sync.js:84–89`; `src/components/InspCard.vue:16–18`.

Два глубоких наблюдателя следят за базой целиком. Локальный — сериализует весь список с задержкой 50 мс, облачный — обходит ID и синхронно сохраняет метаданные. При обычном наборе текста пауза между символами может быть больше 50 мс, поэтому сохранения происходят часто. При росте истории стоимость растёт вместе со всей базой. [Документация Vue](https://vuejs.org/guide/essentials/watchers#deep-watchers) отдельно предупреждает о стоимости глубокого обхода.

Исправление: отмечать изменённые осмотры непосредственно в функциях мутаций, сохранять по ID; применять разумное пакетирование с немедленным flush при скрытии страницы. При больших объёмах перейти на IndexedDB. Общие результаты вычислять один раз: карточка сейчас отдельно строит этапы для отчёта и прогресса.

Проверка: измерить задержку ввода и время сохранения на 10/100/500 осмотрах. До измерений виртуализация и смена библиотеки состояния не обязательны.

**12. P2 — автопрокрутка чата мешает чтению и создаёт лишнюю работу. Подтверждено кодом.**

Место: `src/views/AssistantView.vue:45–48,71`.

Каждое изменение длины ответа запускает `nextTick`, чтение `scrollHeight` и плавную прокрутку вниз, независимо от того, читает ли пользователь старые сообщения. При потоке это часто повторяющиеся операции.

Исправление: следовать за ответом только если пользователь уже у нижней границы; иначе показывать кнопку «Новые сообщения». Объединять обновления в один кадр, не запускать новую smooth-прокрутку на каждый фрагмент.

**13. P2 — светлой теме нужны отдельные цвета текста для ссылок и статуса успеха. Подтверждено расчётом.**

Места: `src/assets/styles/tokens.css:122–127`; `src/assets/styles/components.css:62,158`; `src/assets/styles/screens.css:109`; `src/components/PriceBlock.vue:26`.

Контраст оранжевого `#E85F00` на белом — **3,46:1**, а `.link` использует его для текста 15 px. Пример — ссылка объявлений на карточке цены. Зелёный `#1E8E4E` на белом — **4,17:1**; на собственной светло-зелёной подложке контраст ещё ниже. Это затрагивает небольшие надписи статуса. Для обычного текста ориентир — 4,5:1 по [WCAG](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum).

Исправление: разделить токены заливки и текста (`accent` / `accent-text`, `ok` / `ok-text`), подобрать более тёмные текстовые варианты светлой темы. Проверить комбинации на фактических подложках обеих тем. Полностью менять оранжевый акцент не требуется.

**14. P2 — черновик нового осмотра не переживает перезагрузку. Подтверждено кодом.**

Места: `src/store.js:82,105–107`; `src/views/NewCheckView.vue`.

Выбранные двигатель, кузов, год, коробка и введённые сведения живут в `reactive(emptyDraft())`, но не включены в сохраняемое состояние. Перезагрузка или выгрузка вкладки сбрасывает незавершённое создание.

Исправление: сохранять валидируемый черновик, восстанавливать с предложением продолжить/начать заново, очищать после создания. Это особенно полезно для семишагового сценария.

**15. P2 — ошибка сохранения AI-модели скрывается, что угрожает связанному осмотру после перезапуска. Подтверждено кодом.**

Места: `src/store.js:69–74`; `src/logic/storage.js:18,50–54`; `supabase/functions/generate/index.ts:119–121`.

`saveModels()` проглатывает ошибку localStorage. Серверная генерация тоже возвращает успех при ошибке вставки `custom_models`. Пользователь может продолжить работу с моделью, существующей только в памяти. После перезагрузки осмотр неизвестной модели не пройдёт валидацию конфигурации и будет отклонён; его данные могут остаться в резервной corrupt-копии, но из списка он исчезнет.

Исправление: явно отслеживать сохранность модели, не показывать полное сохранение при сбое; сохранять модель и зависимый осмотр согласованно. При загрузке неизвестной модели удерживать запись в состоянии «ожидает справочник», а не подменять модель Golf V.

**16. P2 — асинхронные ошибки инициализации не ловятся существующим try/catch. Подтверждено кодом.**

Места: `src/main.js:56`; `src/cloud/auth.js:58–64`.

`try { init(); }` ловит синхронное исключение, но не отклонение возвращённого Promise. Если асинхронная инициализация авторизации выбросит ошибку, это обойдёт обработчик, а `auth.ready` может не установиться.

Исправление: обрабатывать Promise каждого независимого инициализатора, завершать состояния загрузки в `finally`, давать возможность повтора. Локальное приложение должно оставаться доступным при сетевом сбое.

**18. P3 — адаптивность и типографика требуют проверки в отрисованном интерфейсе. Рекомендации, не подтверждённые визуальные дефекты.**

Места: `src/assets/styles/layout.css:21–24,116,195`; `src/assets/styles/tokens.css:64–72,81`.

Основная колонка ограничена 640 px, нижняя навигация — 420 px. Для мобильного продукта это оправдано. Если десктоп и планшет важны, использовать дополнительную ширину для списка этапов и сводки рядом с контентом, а не растягивать строки текста.

Проверить 200% масштаб, крупный системный текст, ширину 320/375 px, горизонтальную ориентацию и экранную клавиатуру. Отдельно проверить нижние sheets с `100vh`, уменьшение доступной высоты и safe-area в Safari/Telegram. Менять механику клавиатуры без воспроизведения проблемы не стоит.

**19. P2 — тестовая защита не покрывает наиболее рискованные сценарии. Подтверждено составом тестов.**

Места: `vitest.config.js`, `tests/cloud.test.js`, `.github/workflows/deploy.yml`.

Успешный прогон не проверяет смену аккаунта, гонки сетевых запросов, реальные переходы по экранам или политику доступа в развёрнутой базе.

Для серверной части — отдельные тесты квот и RLS. Добавить проверку pull request до слияния: текущий workflow запускается на push в main и вручную. ESLint/vue-tsc или поэтапная типизация полезны после исправления функциональных дефектов; полная миграция проекта ради аудита не нужна.
